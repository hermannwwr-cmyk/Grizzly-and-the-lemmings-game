# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Grizzly and the Lemmings": a set of 14 mini games for a ~6–7-year-old: Catch, Boop!, Match, Count, Add and Take Away (page 1 of the menu), Maze, Simon Says, Bridge, Sudoku, Honey Shop and Leap (page 2), and Rafts and Stack (page 3), played mostly on a tablet. The entire game is one self-contained file, `index.html`: inline CSS and JS on an HTML5 canvas. It has no build step, no dependencies, and no package.json. All in-game art is drawn with canvas primitives, sound is synthesized with WebAudio, and voice uses `speechSynthesis`. The only other files are for hosting: `icons/` (the app icon PNGs and `make-icons.js`), `manifest.webmanifest`, and `.nojekyll`.

Design constraints:
- Gentle for young kids: no game over, no in-game timers, no penalties. Wrong answers get a soft "Try again!" The only clock is the grown-up's daily play-time limit, and it never cuts a child off mid-turn.
- Pre-readers must be able to play: big tap targets, minimal text, and spoken instructions and numbers via `say()`.
- Touch first. Pointer events drive everything. Keyboard support is secondary: arrows/A/D, Enter, Esc, M.
- Characters, tunes and sound effects are original. Don't copy the look or the music of the TV cartoon with a similar name.

## Running and testing

- Run: open `index.html` in a browser, or serve the folder (`python3 -m http.server`).
- There is no test suite or linter. Verify changes with headless Playwright (preinstalled in cloud sessions: `require('playwright')`). Load `file://.../index.html` at a 960×540 viewport, click at logical coordinates, and take screenshots.
- `window.__game` is a test hook. It exposes `go(sceneName)`, `scene` (the current scene key), `overlay` (the current overlay title, or null; non-null means a level or game was finished), `audio`, `music`, `songs`, `playTime`, `modal`, and `art` (`ctx` and the draw functions). Use `art` to render pose sheets: draw and call `canvas.toDataURL()` in the same `evaluate`, before the next frame repaints.
- To reach end screens quickly, test a temporary copy with lowered goals (e.g. with `sed` on `goal:` / `GOAL`). Don't commit lowered goals.
- The play-time limit is on by default (15 minutes a day) and counts while a game is open, so long test runs can hit bedtime. Turn it off with `page.addInitScript(() => localStorage.setItem('grizzly-limit', '0'))`. To test bedtime, seed `grizzly-limit` (minutes) and `grizzly-play` (`{ day, used, extra }`). `day` is `Y-M-D` without zero padding (e.g. `2026-11-13`), `used` is in seconds and `extra` in minutes. A temporary copy with a smaller `BEDTIME_GRACE` (via `sed`) gets to the sleep screen quickly. `__game.playTime` exposes `left()`, `used()` and `limit`, and `__game.modal` gives the grown-up check's `mode` and its `answer`.
- Useful click targets (logical coordinates): menu cards at x 210 / 480 / 750 and y 232 / 418; page arrows at (44, 330) and (916, 330); the home button at (40, 30); the music and speaker buttons at (864, 30) and (920, 30); on a finished-game overlay, Again is at (340, 375) and Home at (620, 375). On the menu and sleep screens the grown-up gear sits where the home button would be, at (40, 30). The gate's keypad keys are at x 358 / 480 / 602 and y 258 / 324 / 390 / 456 (1–9, then Del 0 OK). In the settings, the limit choices Off/10/15/20/30 are at y 184 with x 280–680 in steps of 100; +5 minutes is at (480, 336), Start today again at (480, 402) and Done at (480, 468).
- From `file://`, the manifest and icon links fail with CORS errors in the console. To check them, serve the folder with `python3 -m http.server`.

## Architecture (all inside the IIFE in `index.html`)

- **Fixed logical resolution:** 960×540, with `GROUND = 470`. `resize()` scales the canvas with a DPR-aware `setTransform`, so all game code uses logical coordinates. `toGame()` maps pointer events back into those coordinates.
- **Scenes:** the `S` object holds `menu`, `sleep` (bedtime), and one scene per game key (`catch`, `boop`, `match`, `count`, `add`, `sub`, `maze`, `simon`, `bridge`, `sudoku`, `shop`, `leap`, `rafts`, `stack`). Each scene has `start()`, `update(dt)`, and `render()`, plus optional `pointer(p)` (finger down), `drag(p)` (while down), and `release(p)` (finger lifted) handlers. `go(name)` switches scenes and resets `overlay`, `particles`, and `keys`. Game scenes are IIFEs that keep their state in closure variables.
- **Number games:** Count, Add, and Take Away share `pickChoices`, `drawChoices`, `hitChoice`, `drawCountBadge`, and `drawRoundStars`. Add and Take Away are one factory, `makeMathGame('add' | 'sub')`, which moves each round through the phases `intro` → (`steal`, Take Away only) → `ask` → `right`, and ends with `done`. Difficulty tables are at the top of the factory. Operands are single digits and answers stay at 10 or below. Bridge and Honey Shop also keep their sums at 10 or below.
- **Voice:** `say(words, queue)` cuts off current speech unless `queue` is true. `go(name, intro)` says the intro first, so a scene's opening line should use `queue = true` if it must not cut the intro off.
- **Adding a game:** games after Take Away are self-contained plug-in blocks below the `// @@NEW-GAMES@@` marker. Each block defines `S.<key>`, then `GAMES.push({key, label, bg, edge, ink, voice})` (menu order = push order), `PREVIEWS.<key> = (cx, top) => …` (card art, drawn for a 200×280 card), and `SONGS.<key>` (its tune). Add new games the same way. Block-level helpers are prefixed or uniquely named (`drawDrum`, `drawCoin`, `leapDraw…`, `raftsDraw…`) because they share the IIFE scope.
- **Menu pages:** 6 cards per page (`PER_PAGE`). The arrows, a sideways swipe, and the ←/→ keys flip pages. The swipe is handled by the global pointer handlers through the `swipe` state: cards follow the finger via `menuDrag`, `menuSlide` eases the new page in, and once a press has moved sideways it no longer opens the card it started on. `menuPage` is remembered when you come back from a game. Tests that return home stay on the same page.
- **Audio unlock (iOS):** `initAudio()` runs on every pointer, touch, click, and key event. It sets `navigator.audioSession.type = 'playback'`, plays a silent buffer and a silent `<audio>` element, and primes `speechSynthesis`, so sound works on iPads and iPhones even in Silent Mode. Buttons fire on **pointerup**, not pointerdown, because iOS only allows audio and speech to start when the finger lifts. Keep it that way. Scene taps (`scene.pointer`) still fire on pointerdown.
- **Background music:** `SONGS` holds one original 8-bar tune per scene key (bpm, lead waveform, volume, note length, bass rhythm, melody, and bass roots). `go()` sets `songKey`. `updateMusic()` runs from the main `update()`, restarts the tune from the top when the scene changes, and schedules notes about 0.25 s ahead into `musicGain`. Music dips to 30% while `speechSynthesis.speaking` and is silent when `muted` or `!musicOn`. The music button sits beside the speaker button, and the on/off choice is saved in `localStorage['grizzly-music']`. A new scene needs a `SONGS` entry, or it falls back to the menu tune.
- **Immediate-mode buttons:** the `buttons` array is cleared every frame in `render()` and refilled by `button()`, `drawHome()`, `drawMute()` (which also draws the music button), and the menu cards. `pointerdown` hit-tests that array (topmost first). A pressed button fires on pointerup. Anything else is forwarded to `scene.pointer`. Anything clickable has to be pushed during render.
- **Overlay:** `overlay = { title, sub, win, buttons: [{label, color, action}] }` is drawn on top of the current scene. While it is set, scene input is blocked and scenes should early-return from `update`. Use `celebrate(key, title, sub)` to finish a game: it plays the fanfare, awards a star, starts confetti, and shows the Again/Home buttons. Catch also uses a non-win overlay between its levels.
- **Shared drawing helpers:**
  - Cartoon style: `blob()` fills an ellipse and outlines it in `INK`, `shade()` makes the soft top-left lighting, and `blinking(seed)` drives blinks. Shapes are drawn back to front, so each fill covers the outlines behind it.
  - Characters and objects: `drawBackground`, `drawBear(x, groundY, scale, {facing, walk, moving, happy, dance, pose, squash, look})`, `drawLemming(m)` / `drawLemmingAt(x, y, scale, m)`, `drawTreat(type, …)`, and `drawHole` (a clipped pop-up critter).
    - Bear `pose`: `'rest' | 'up' | 'dance' | 'scratch'` (puzzled, after a wrong answer) `| 'rub'` (tummy rub, after a catch) `| 'sleep'` (bedtime).
    - Lemming `m.face`: `'happy' | 'dizzy' | 'cheeky' | 'sleep'`. Carrying a treat makes a lemming cheeky (wink and tongue out). Give each lemming a `seed` so blinks and ear wiggles stay out of sync.
    - `squash` (> 0 flat, < 0 tall) on both gives the squash-and-stretch. `updateHop` / `hopSquash` share the hop physics for tappable things.
  - Text and shapes: `text()` (stroked text), `drawStar`, and `drawHeart`.
  - Effects: `burst`, `floatText`, `puff` (dust clouds for skids, landings and bumps), and the particle system.
  - HUD: `drawProgress`.
- **Persistence:** star counts per game are kept in `localStorage['grizzly-stars']`, the play-time settings in `grizzly-limit` and `grizzly-play`, and the music choice in `grizzly-music`. Every access is wrapped in try/catch, and the game must work without storage (the play-time limit then lasts for the visit).

### Play time (set by a grown-up)
This copies the design of the owner's MRT-GAME.
- **Setting:** 15 minutes a day by default (`DEFAULT_LIMIT`). On the menu and sleep screens, the gear button (`drawGearButton`, where the home button is in games) opens `modal`. That's a grown-up check first: a times-table sum from 6–9 × 6–9, typed on an on-canvas keypad; a wrong answer shakes and gives a new sum. Then the settings: a daily limit of Off/10/15/20/30 (`LIMIT_CHOICES`), today's use, "+5 minutes today" and "Start today again". While `modal` is open, it clears `buttons`, blocks scene input and swipes, and takes the keyboard (digits, Backspace, Enter, Esc to close).
- **Counting:** `playTime` keeps the limit and today's record (a new day starts fresh). `updatePlayTime()` adds whole seconds only while `inGame()`, no modal is open and the page is visible, so reloading doesn't reset it. `drawPlayClock()` shows an m:ss chip at the top centre during games; it turns orange with a moon in the last minute. While it shows (`clockOnTop()`), `drawRoundStars`, Catch's level stars and Leap's progress track move aside: the stars go just right of the clock, and Leap's track drops 52px. New games should keep the top centre (about x 415–545, y 10–50) clear, or check `clockOnTop()` the same way. `drawMenuTime()` shows the minutes left on the menu.
- **Sky clock:** `drawBackground(phase = playTime.share())` takes the sky from morning to afternoon to evening to night as the time is used up (`SKY`, `skyAt`), with the sun setting, moon and stars, and a night tint. Scenes with their own backgrounds keep them.
- **Ending:** at `LAST_MINUTE` (60 s) Grizzly says he's getting sleepy. At 0, the child finishes: the next end-of-level or end-of-game overlay shows for 3 s, or `BEDTIME_GRACE` (45 s) runs out, then `go('sleep')`. The sleep scene shows Grizzly (`pose: 'sleep'`) and lemmings (`face: 'sleep'`) asleep under the stars, with a lullaby (`SONGS.sleep`).
- **Locked:** while `playTime.left() <= 0`, `go()` sends any game to `sleep`, the game opens on `sleep`, and Esc does nothing there. Closing the settings with time left wakes Grizzly and returns to the menu. Like MRT, this can't stop someone who clears the site's data; for a hard lock, use the device's own screen-time controls.

## Published copy

- **GitHub Pages (public):** served straight from the repo root on branch `claude/quirky-feynman-uv30aq`: https://hermannwwr-cmyk.github.io/Grizzly-and-the-lemmings-game/. Every push to that branch redeploys it, usually within a minute. A repo stop hook asks for all changes to be committed and pushed, so a finished change goes public. To show a preview first, publish only the claude.ai copy below, and push once the owner agrees. You can confirm a deploy by checking that the "pages build and deployment" workflow run for that commit succeeded. `.nojekyll` turns off GitHub's Jekyll processing.
- **App icon:** the `<head>` links `icons/favicon-32.png`, `icons/apple-touch-icon.png` and `manifest.webmanifest` (fullscreen, landscape). The icon is drawn by the game's own code; regenerate it with `node icons/make-icons.js` after changing how Grizzly or the lemmings look.
- **claude.ai Artifact (private copy):** the host supplies the document skeleton and blocks outside files. Build the copy by deleting the skeleton and the icon tags:
  ```
  sed -e '/<!DOCTYPE html>/d' -e '/<html lang/d' -e '/<\/\?head>/d' -e '/<\/\?body>/d' -e '/<\/html>/d' \
      -e '/<meta charset/d' -e '/<meta name="viewport"/d' -e '/<link rel=/d' \
      -e '/<meta name="theme-color"/d' -e '/<meta name="apple-mobile-web-app/d' index.html > grizzly-game.html
  ```
  Keep `<title>` and `<style>` near the top of `index.html`, and keep each of those head tags on its own line, so this stays a simple line deletion. Keep all game code and art inline.
